## What to fold into `design_system/public/TASTE.md`

TASTE.md (read before this research, dated 2026-09-01) already covers: distributional
convergence as the root cause, the builder ritual, the separate-evaluator rubric, banned
tells (walls of text, scrolling lists, KPI grids, the stacked-section page, gradients,
Inter/Roboto, card grids with icons, shadow soup, centered-everything heroes, emoji
headers, hover bounce), the "3-5 references with what specifically works" discipline, and
the variants-then-one-winner rule. The items below are **not** already there:

1. **Two more named tells, specific enough to check for directly:** *frosted-glass /
   glassmorphism panels* (translucent blurred cards) and *uniform rounded-corner cards as
   the whole visual system* (every container gets the same radius regardless of content) —
   both called out by name in the highest-substance post found (@vikktorrrre). TASTE.md's
   current list has "gradients" and "card grids with icons" but not these two.
2. **Sharpen "gradients" to name the specific offender:** a *purple/violet gradient
   specifically at the top of the page* is the tell people actually screenshot and mock —
   worth naming explicitly rather than leaving "gradients" generic.
3. **A second reference technique, more concrete than "write 3-5 sentences":** point the
   agent at real, live component-library code (shadcn/ui, Aceternity, Magic UI,
   beautifui.dev, rareui.com) and have it fetch and adapt actual markup/CSS rather than
   generate from a text description. This is the technique behind the single
   highest-engagement post in the whole pass (@EXM7777, 961K views) and it is a materially
   different production method from "write references down."
4. **A third reference technique:** machine-readable `DESIGN.md`-style token files scraped
   from real shipped sites (colors, type, spacing, component inventory) as drop-in
   pre-build context, distinct from prose references or component code (@ImranUxi).
5. **Name the failure mode of relying on someone else's skill file:** "does a skill file
   fix taste, or just swap one default aesthetic for another? Same convergence problem,
   just a different template" (@raphydanilo, unanswered in its own thread). Worth stating
   directly: an installed generic taste/anti-slop skill is a starting constraint, not a
   substitute for Ryan Realty's own references (brand tokens, hero photography, Central
   Oregon subject matter) — used alone it just produces a different, but still uniform,
   look shared by everyone who installed the same skill.
6. **A sharper one-line statement of the mechanism**, worth having as a pull-quote:
   "the AI doesn't invent criteria; it averages them" (@opcastil) — same idea as TASTE.md's
   "distributional convergence" but shorter and more citable for a builder/evaluator
   prompt.
7. **Add a corner-radius/spacing consistency check to the craft criterion**: not just "on
   the token scale" but *matches across every card, button, and panel visible together in
   one viewport* — the one concrete nitpick a real commenter raised on an otherwise
   well-received UI (@AndrewPulc).
8. **Process note for future research, not a design rule:** this corner of X is heavily
   marketing-driven — multiple accounts post near-identical copy for the same product
   within days of each other, and specific numbers (GitHub stars, "10x," view counts as
   quality proof) are unverified and often implausible. Treat any specific adoption number
   sourced from an X post as a marketing claim, not evidence, unless cross-checked against
   the actual repo.
