# Process: cookie-consent — Cookie consent capture and tracker gating

## 0. Meta

- Status: deepened
- Cadence: continuous — the capture moment fires once per new visitor (or per cookie expiry), but the recorded state is consulted on every pageview by five client consumers and enforced on every first-party tracking write by the server.
- Verdict (PROPOSAL, not a lock): **KEEP** — the consent state is the legal switchboard for four third-party tracker stacks (GA4/Google Ads, GTM, Meta Pixel, AdSense) AND the first-party visitor_events intent pipeline that feeds hot-lead scoring. It cannot merge into `serve-legal-pages` (that process serves policy *content*; this one is a runtime *state machine* the trackers execute against) and it cannot be killed (CCPA/CPRA do-not-sell surface, GPC enforcement). The §10 defect list — most seriously the broken withdrawal promise (D1) — is P4/P9 repair work inside a KEEP, not a reason to restructure.
- Last evidence pass: 2026-08-11 (every file:line below opened this run)

## 1. Purpose

(a) A first-time visitor makes one honest, one-tap privacy choice — accept all, essential only, or granular analytics/marketing via a preferences dialog — with the full policy and a Do-Not-Sell path one link away, and is then never asked again for a year (components/CookieConsentBanner.tsx:172-186, :18). (b) The machine outcome is a recorded consent state that lawfully switches on the widest tracking the visitor allowed — GA4 Consent Mode v2 grants, GTM load, Meta Pixel LDU mode, AdSense render, and the consent level stamped on every first-party visitor event that drives intent scoring and hot-lead alerts — so fully serving (a) is precisely what licenses the attribution and behavioral data every capture and conversion process in this registry depends on (components/GoogleAnalytics.tsx:46-65; components/VisitTracker.tsx:199-234; app/api/visitors/track/route.ts:148-149).

## 2. Inception (what starts it)

Three distinct triggers, one shared state machine:

1. **Banner trigger (the UI path).** First hydrated pageview on any route outside `/lp/*`, `/admin`, `/sign/*`, `/concept/*` by a browser with no `ryan_realty_cookie_consent` cookie. The banner mounts globally: app/layout.tsx:135 wraps the whole body in RootProvider; RootProvider renders `<CookieConsentBanner/>` inside `<HideOnLP>` (components/site/providers/RootProvider.tsx:40-42); HideOnLP nulls out on lp/admin/sign/concept paths (components/layout/HideOnLP.tsx:27-35). The component itself decides visibility in a mount effect — cookie absent → `setVisible(true)` (components/CookieConsentBanner.tsx:110-117). Entry channel: any (organic, direct, referral, internal).
2. **Ad-traffic auto-grant (no UI — Matt directive 2026-06-02, recorded in the code docblock).** Arrival with `fbclid`/`gclid`/`msclkid`/`ttclid`/any `utm_*` param and no prior explicit choice: `autoGrantConsentForAdTraffic()` writes analytics+marketing consent and dispatches the `cookie-consent` event on the same page load (components/CookieConsentBanner.tsx:76-87), called from VisitTracker's main effect (components/VisitTracker.tsx:262). VisitTracker mounts via PublicClientLayer *outside* any HideOnLP wrapper (components/layout/PublicClientLayer.tsx:56, mounted at app/layout.tsx:166), so the auto-grant runs on `/lp/*` routes too — paid arrivals take this path everywhere. An explicit prior choice is never overridden (:78).
3. **GPC opt-out (no UI, opposite direction).** A request carrying `Sec-GPC: 1` (or the forwarded `navigator.globalPrivacyControl` flag) is a legally binding do-not-sell signal in CA/CO/CT: the track endpoint drops the event entirely and, if the session is identified to a CRM person, records a durable `channel='all'` suppression — regardless of what the consent cookie says (app/api/visitors/track/route.ts:270-301; pure decision surface lib/crm/gpc.ts:1-40).

Preconditions: JavaScript enabled — the banner is a client component that renders nothing server-side and appears only after its mount effect (components/CookieConsentBanner.tsx:104-117,138). A noscript visitor never sees a consent surface at all, yet the Meta noscript pixel image still fires (components/MetaPixel.tsx:54-63) — see §10 D10.

## 3. Actors

- **Visitor personas** (all segments, all devices — this is the one process every visitor enters): (1) the **ignorer** — never answers the banner; treated as consent level `'essential'` so the minimal first-party record still writes (components/VisitTracker.tsx:102); (2) the **accepter** — one tap on Accept all; (3) the **decliner** — Essential only; (4) the **granular chooser** — opens the Preferences dialog and toggles analytics/marketing separately (components/CookieConsentBanner.tsx:143-161); (5) the **ad-clicker** — auto-granted with no UI (§2.2); (6) the **GPC-armed browser** — server-side opt-out with no UI (§2.3). Device split from GA4 for banner interactions was **not queried this pass** — a stated gap, not a number.
- **Automated actors:** VisitTracker's auto-grant effect (components/VisitTracker.tsx:257-262); gtag's Consent Mode machinery (denied defaults injected `beforeInteractive`, components/GoogleAnalytics.tsx:80-109); the track endpoint's server-side consent enforcement (app/api/visitors/track/route.ts:247-261). No crons touch this process.
- **Accountable for completion:** Matt (licensed principal broker) owns the compliance posture — including the standing 2026-06-02 directives that the Pixel fires on all traffic and ad arrivals are auto-granted (components/MetaPixel.tsx:12-17; components/CookieConsentBanner.tsx:68-75). The code owns enforcement.

## 4. Systems of record

- **Consent state SoR:** the `ryan_realty_cookie_consent` first-party cookie — JSON `{analytics, marketing}`, 1-year expiry, `path=/`, `SameSite=Lax`, no `Secure` attribute (components/CookieConsentBanner.tsx:17-18,46-50). A legacy raw value `'all'` is still parsed for old visitors (:41). This client-held cookie is the ONLY record of the choice — no DB table stores it (the three choice handlers write the cookie and dispatch an event, nothing else: :119-136).
- **In-flight propagation bus (not a store):** the `cookie-consent` CustomEvent on `window` — every listener re-reads the cookie via the exported getters rather than trusting the event detail (components/GoogleAnalytics.tsx:63; components/GTMHead.tsx:22; components/AdUnit.tsx:34; components/PageViewTracker.tsx:67; components/VisitTracker.tsx:306; components/LandingPageTracker.tsx:109).
- **Third-party consent ledgers:** Google's gtag consent state (defaults denied → `consent update` per choice, components/GoogleAnalytics.tsx:53-58,91-99); Meta's `dataProcessingOptions` LDU flag, set once at pixel init from a raw cookie re-parse (components/MetaPixel.tsx:43-49).
- **Server-side artifacts:** every first-party event POSTs its consent level, which the route requires and enforces (app/api/visitors/track/route.ts:148-149,247-261); GPC opt-outs by identified people become durable `crm_suppressions` rows via `recordGpcSuppression` (route.ts:284-295).
- **Explicitly NOT SoR:** the /cookies page inventory is a hand-maintained *claim* about cookies, not a registry the code reads (app/cookies/page.tsx:38-103) — and it already drifts (§10 D2). The event detail string (`'all'`/`'essential'`) is not authoritative — an analytics-only save dispatches `'essential'` (components/CookieConsentBanner.tsx:135), which is why listeners re-read the cookie.

## 5. End-to-end path (inception → completion)

1. **Arrive + hydrate** · system · route renders; RootProvider mounts the banner slot inside HideOnLP · input: the request · output: banner component mounted (or nulled on lp/admin/sign/concept) · system: app/layout.tsx:135, components/site/providers/RootProvider.tsx:40-42, components/layout/HideOnLP.tsx:27-35 · failure: JS disabled → no consent surface ever (§10 D10) · device: any.
2. **Visibility decision** · system · banner's mount effect reads the cookie: absent → `setVisible(true)`; present → hydrate the dialog's checkbox state and stay hidden · input: `document.cookie` · output: banner shown or suppressed · system: components/CookieConsentBanner.tsx:110-117,138 · failure: cookie parse error falls back to `{analytics:false, marketing:false}` (:42) — fails closed · device: any; on mobile the fixed bar overlaps bottom chrome, mitigated by the compact layout + z-90 stacking noted in the design-audit comments (:163-171).
3. **Ad-traffic auto-grant race** · automated · VisitTracker (dynamically imported, `ssr:false` — components/layout/PublicClientLayer.tsx:29) runs `autoGrantConsentForAdTraffic()` on a later tick than the banner's mount effect; with a click-id/utm param and no prior choice it writes analytics+marketing and dispatches the event · input: `window.location.search` · output: consent granted with no UI · system: components/VisitTracker.tsx:262; components/CookieConsentBanner.tsx:76-87 · failure/nuance: the banner has no `cookie-consent` listener (whole file read this run), so on a non-LP ad landing the already-visible banner stays up even though consent was just granted underneath it (§10 D6); an explicit click still just overwrites the cookie · device: any.
4. **Choose** · visitor · taps one of three equal buttons — Accept all / Essential only / Preferences (dialog with two checkboxes → Save) · input: the tap · output: `setConsentState()` writes the 1-year cookie, banner hides, `cookie-consent` CustomEvent dispatched (detail `'all'` or `'essential'`) · system: components/CookieConsentBanner.tsx:119-136,143-161,180-184 · failure: none observed client-side; the choice is never mirrored to any server store (§10 D9) · device: any.
5. **Propagate to trackers (same pageview)** · automated · six listeners react: GoogleAnalytics `applyConsent()` pushes `gtag('consent','update', …)` mapping marketing→`ad_storage`/`ad_user_data`/`ad_personalization`, analytics→`analytics_storage` (components/GoogleAnalytics.tsx:46-65); GTMHead loads the GTM container once analytics is granted (components/GTMHead.tsx:11-26); AdUnit re-evaluates `hasMarketingConsent()` and renders/collapses the slot (components/AdUnit.tsx:30-36,75); PageViewTracker fires the one-time catch-up `page_view`/Pixel PageView the initial load skipped (components/PageViewTracker.tsx:53-69); VisitTracker re-fires the visitor event a declined load had skipped, dedup-guarded by ref (components/VisitTracker.tsx:293-308); LandingPageTracker (LP only) re-attempts its `view_landing_page` fire (components/LandingPageTracker.tsx:101-134) · failure: Meta's LDU flag is NOT re-applied here — the IIFE ran once at pixel init (§10 D3) · device: any.
6. **Enforce server-side (every subsequent event)** · automated · each first-party event carries `consent` computed by `consentLevel()` (null→`'essential'`, both→`'all'`, analytics-only→`'analytics'`, marketing-only→`'essential'`, neither→`'declined'` — components/VisitTracker.tsx:92-107); the route refuses `declined`/missing (`{ok:true, dropped:true}`, app/api/visitors/track/route.ts:250-258), strips UTMs/geo/listing meta/scroll/dwell under `'essential'` (:259-261, :306), and the GPC gate drops everything + records suppression regardless of cookie state (:270-301) · failure: a misbehaving client is caught by the server gate (the docblock's stated design, components/VisitTracker.tsx:190-193) · device: any.
7. **Return visits (the silent replay)** · system · cookie present → banner never renders; GoogleAnalytics `applyConsent()` on mount replays the stored choice into gtag before the 500ms `wait_for_update` window closes (components/GoogleAnalytics.tsx:61-62,91-99); MetaPixel's init IIFE re-reads the raw cookie on each full page load and sets or clears LDU (components/MetaPixel.tsx:43-49) · output: identical tracking posture with zero visitor interaction until cookie expiry (1 year) · failure: there is no UI to revise the choice in the meantime (§10 D1) · device: any.

## 6. Decision points

- **Cookie present?** → banner suppressed; stored state replayed (components/CookieConsentBanner.tsx:110-117; components/GoogleAnalytics.tsx:61-62).
- **Ad params + no prior choice?** → auto-grant both categories. **An explicit prior choice always wins** — the guard returns early when any cookie exists (components/CookieConsentBanner.tsx:78).
- **Which button?** → accept-all / essential-only / granular dialog; granular allows analytics-only and marketing-only combinations (components/CookieConsentBanner.tsx:119-136,149-156).
- **First-party consent level mapping** (components/VisitTracker.tsx:92-107): no answer → `'essential'` minimal record (deliberate — treating silence as declined made every banner-ignorer invisible and broke email-click identity stitching, per the 2026-07-10 E2E finding recorded at :96-101); marketing-only → `'essential'` (a quirk — §10 D5); declined → nothing leaves the client, and the server refuses it anyway.
- **GPC?** → overrides everything server-side: event dropped, durable suppression when the person is identified (app/api/visitors/track/route.ts:270-301).
- **Compliance gates binding this process:** the banner and dialog copy are public copy under the voice canon (CLAUDE.md §2); the CCPA/CPRA Do-Not-Sell link must be present in the banner (components/CookieConsentBanner.tsx:178 → app/privacy/page.tsx:131-137); Meta traffic without marketing consent runs in LDU mode (components/MetaPixel.tsx:37-49); the deliberate posture that the Pixel and GA4 load pre-consent (LDU / Consent-Mode-denied respectively) is Matt-directed 2026-06-02 with the privacy page's disclosure as the counterweight — EU-style consent-before-fire is explicitly not implemented (components/MetaPixel.tsx:19-21); admin routes carry no trackers at all (components/site/providers/RootProvider.tsx:31-33; components/layout/HideOnLP.tsx:76-80) and VisitTracker skips `/admin` pathnames (components/VisitTracker.tsx:264). §0: the surface carries no market stats — nothing to trace.

## 7. Completion

Done-when (observable):

1. The `ryan_realty_cookie_consent` cookie exists with a JSON `{analytics, marketing}` value and a ~1-year expiry (components/CookieConsentBanner.tsx:46-50).
2. A `cookie-consent` CustomEvent was dispatched and the listeners converged: gtag's consent state matches the choice (components/GoogleAnalytics.tsx:53-58), GTM loaded iff analytics granted (components/GTMHead.tsx:26), AdUnit renders iff marketing granted (components/AdUnit.tsx:75), and the catch-up page-view/visitor-event fires ran where consent newly permitted them (components/PageViewTracker.tsx:53-69; components/VisitTracker.tsx:293-308).
3. The banner does not re-appear on any subsequent pageview until the cookie expires or is cleared (components/CookieConsentBanner.tsx:110-117,138).
4. **Precision correction to the P1 registry sentence:** Meta's LDU `dataProcessingOptions` is set or cleared *at pixel-init time on each full page load* by re-reading the cookie/ad params (components/MetaPixel.tsx:43-49) — a consent choice made mid-session does not retroactively update it until the next full load; only subsequent `fbq` PageView *events* are gated live (components/PageViewTracker.tsx:50,61-64).

Terminal states: granted-all · analytics-only · marketing-only · declined (essential-only) · auto-granted (ad traffic) · GPC-suppressed (server-side, cookie-independent). Artifacts at completion: the consent cookie; Google's consent state; visitor_events writes stamped with the consent level; a `crm_suppressions` row for an identified GPC opt-out (app/api/visitors/track/route.ts:284-295).

## 8. Time & performance

- **Time-to-answer for the visitor's implicit question ("what will you track, and what are my choices?"):** one short sentence + two policy links + three equal buttons, answerable in a single glance and one tap (components/CookieConsentBanner.tsx:174-184). The granular path adds one dialog.
- **Render timing:** the banner is client-only and appears after hydration — it can never block first paint or be the LCP element, and as a `position:fixed` bottom bar it contributes zero CLS by construction (components/CookieConsentBanner.tsx:172). The compact layout exists specifically so the bar stops covering the mobile hero's proof line and CTA pair at first paint (design-audit note in the component, :166-168).
- **The engineered race budget:** gtag holds all tracking pings up to **500ms** (`wait_for_update`) while the stored consent cookie is read and re-applied, so a returning opt-in visitor's first ping carries the right state (components/GoogleAnalytics.tsx:91-99). URL-passthrough and ads-data-redaction keep attribution and compliance intact for denied states (:100-107).
- **What "slow" means here:** on slow devices the choice arrives late, and lateness *fails safe for privacy* — GA defaults stay denied, Meta's heuristic runs LDU for non-ad traffic — at the cost of data (the skipped initial page-view only recovers via the one-shot consent-event catch-up, components/PageViewTracker.tsx:53-69). The visitor is never blocked; the machine pays.
- **Stated gaps, not numbers:** no CWV was queried for entry routes this pass (the process is global, so its CWV reality is every route's), and no GA4/visitor_events figures for acceptance, decline, or ignore rates were pulled — nothing in the repo measures the choice event itself (§11 data gap).

## 9. Variants

All variants converge on the same cookie state machine; no split is warranted.

- **Organic/direct/referral first visit** — the banner path (§5.2-5.4).
- **Paid arrival, non-LP route** — auto-grant fires; banner may still show over an already-granted state (§10 D6); an explicit click simply overwrites.
- **Paid arrival, /lp/** route** — no banner ever (components/layout/HideOnLP.tsx:27); auto-grant and all trackers still run (components/layout/PublicClientLayer.tsx:56); the LP's own capture contract and disclosures belong to `arrive-from-ad`.
- **Return visitor** — silent replay (§5.7).
- **GPC browser** — server-side opt-out regardless of any cookie (app/api/visitors/track/route.ts:270-301).
- **Noscript visitor** — no consent surface exists; the Meta noscript pixel fires unconditionally (components/MetaPixel.tsx:54-63) — §10 D10.
- **Legacy cookie holder** — raw `'all'` value still parses as full consent (components/CookieConsentBanner.tsx:41).
- **Admin / sign / concept** — no banner; admin additionally carries no analytics stack at all (components/site/providers/RootProvider.tsx:28-33).

## 10. Current implementation map

- **Surfaces:** a global overlay (banner + preferences dialog) mounted once via RootProvider — no route of its own. Built from `@/components/ui/*` primitives (Button, Dialog, Checkbox, Label — components/CookieConsentBanner.tsx:5-15), i.e. the compliant design-system register, not kb/legacy/v2.
- **Producers of consent state:** the three banner handlers (components/CookieConsentBanner.tsx:119-136) and the auto-grant (:76-87, invoked components/VisitTracker.tsx:262).
- **Consumers:** GoogleAnalytics, GTMHead, MetaPixel (inline re-parse), AdUnit, PageViewTracker, VisitTracker, LandingPageTracker on the client; `/api/visitors/track` on the server (all cited in §5).
- **Known defects, each verified this run:**
  - **D1 — the withdrawal promise is broken.** /cookies tells visitors they can change consent "by … returning to the banner" (app/cookies/page.tsx:156-157) and /privacy#donotsell instructs "set Marketing to off in our cookie banner" (app/privacy/page.tsx:137) — but after any choice the banner renders `null` for a year (components/CookieConsentBanner.tsx:110-117,138) and a repo grep this run found no other component that re-opens it or the preferences dialog. A normal visitor cannot withdraw consent without manually deleting the cookie. This is the process's biggest defect: a compliance-page promise with no mechanism.
  - **D2 — disclosed cookie nothing sets.** `ryan_realty_visit_id` is listed in the /cookies inventory (app/cookies/page.tsx:69-74), but its writer `getOrCreateVisitId` has zero callers repo-wide (grep this run) — a dead export (components/CookieConsentBanner.tsx:89-102) and an inventory row describing a cookie no live path creates.
  - **D3 — Meta LDU is one-shot.** The LDU decision runs once inside the pixel-init script (components/MetaPixel.tsx:43-49) and no listener re-applies it: an Essential-only choice made after an ad-param landing stays non-LDU until the next full page load (the compliance-relevant direction), and an Accept-all after a cold landing stays LDU (the data-loss direction).
  - **D4 — duplicated consent logic.** MetaPixel re-implements cookie parsing and ad-param detection inline (components/MetaPixel.tsx:45-47) instead of importing the shared helpers; its regex (`/[?&](fbclid|gclid|msclkid|ttclid|utm_)/i`) is a second, subtly different implementation of the predicate at components/CookieConsentBanner.tsx:80-82. Two implementations of one legal rule is drift waiting to happen.
  - **D5 — marketing-only maps to `'essential'`.** A granular chooser who grants marketing but not analytics gets minimal first-party records (components/VisitTracker.tsx:105) while the Pixel runs at full consent — internally inconsistent semantics for the same person.
  - **D6 — auto-grant/banner race.** VisitTracker loads via `dynamic(..., {ssr:false})` (components/layout/PublicClientLayer.tsx:29) so the auto-grant runs after the banner's visibility effect, and the banner has no `cookie-consent` listener — on non-LP ad landings the banner shows over already-granted consent. Harmless (explicit click overwrites) but incoherent.
  - **D7 — cookie lacks the `Secure` attribute** (components/CookieConsentBanner.tsx:49).
  - **D8 — GTMHead is one-way:** it flips to loaded on grant and ignores later revocation within the session (components/GTMHead.tsx:14-24) — currently moot because D1 means revocation UI doesn't exist.
  - **D9 — no consent audit trail.** The choice handlers write only the client cookie + event (components/CookieConsentBanner.tsx:119-136); no server record of the choice or its changes exists, so the site cannot demonstrate when a given visitor consented.
  - **D10 — noscript pixel is unconditional.** The `<noscript>` Meta image fires PageView with no consent evaluation possible (components/MetaPixel.tsx:54-63).
- **Duplicate/parallel paths that should die:** MetaPixel's inline consent re-parse (fold into the shared helpers at next touch — D4); the dead `getOrCreateVisitId` export (D2).

## 11. Target shape (process-level, not pixels)

- **Should this exist?** Yes — KEEP (§0 verdict). It is the legally required interruption the lead machine must make, and the license for the machine's entire behavioral data supply.
- **Ideal shape (derived from the job, not today's files):** ONE shared consent module — single parse/serialize, single ad-param predicate, single level-mapping — consumed by every tracker and the pixel init (kills D4/D5); a **persistent, discoverable "Cookie preferences" affordance** (footer legal row + /privacy + /cookies links re-opening the same dialog) so the withdrawal path the policy pages already promise actually exists (kills D1, makes D8 real); LDU re-applied on consent change (kills D3); the choice optionally mirrored to a server-side record for auditability (kills D9); the cookie inventory generated from, or gate-checked against, what the code actually sets (kills D2).
- **Ideal step count/device:** first-visit choice stays 1 tap (≤2 steps granular), mobile-first at 390; withdrawal ≤2 taps from any page footer. The banner remains one line + three equal actions — never a modal wall, per the north star that the machine "never acts like it" (decisions.md 2026-08-11 directive 3): this is the one interruption, so it must be the smallest possible one.
- **Data gaps blocking correctness:** nothing measures the consent choice itself — no acceptance/decline/ignore rates exist anywhere found this run, so the real-world split across §7's terminal states is unknown; GA4 device mix for banner interactions unqueried. Both are ✗ statements for P4, not designs.
- **Destination implication:** **NO destination of its own** — this process ships as a global overlay plus a settings affordance reachable from the legal pages and the footer. It has no page, but as a viewport-claiming surface it stamps a dual objective of its own:
  - `visitor_objective`: "Make one honest, quick privacy choice — and be able to change it any time."
  - `machine_objective`: "Record a consent state that lawfully switches on the widest tracking the visitor allowed, feeding attribution, retargeting, and intent scoring."
  - `exits`: `/privacy` · `/privacy#donotsell` · `/cookies` (today unlinked from the banner — reachable only via /privacy body prose, a serve-legal-pages finding) · dismissal-by-choice back to the underlying page (the choice IS the exit; there is deliberately no close-without-choosing control).
- **Binding decisions:** no line in docs/plans/PUBLIC_PRODUCT/decisions.md constrains this surface beyond the global directives (one lead machine that never acts like it; mobile 390 is truth; voice canon). Matt's 2026-06-02 directives — Pixel on all traffic, ad-traffic auto-grant — are recorded product truth in the code docblocks (components/MetaPixel.tsx:12-17; components/CookieConsentBanner.tsx:68-75) and stand until Matt revisits them; the P3 package should surface D1 (broken withdrawal promise) and D10 (noscript pixel) to him explicitly since both touch the compliance posture he owns.

## 12. Acceptance checks

Persist; never delete. Checks 6-7 must send a real-browser User-Agent — the WAF blocks default curl UAs (known drift lesson).

1. **Banner appears for a fresh visitor.** Browser with cleared cookies → `https://ryan-realty.com/` → an element with `role="region"` and accessible name "Cookie notice" is visible; `document.cookie` contains no `ryan_realty_cookie_consent`.
2. **Accept-all completes the state machine.** Click Accept all, then in the console: `decodeURIComponent(document.cookie.split('; ').find(r=>r.startsWith('ryan_realty_cookie_consent=')).split('=')[1])` → `{"analytics":true,"marketing":true}`; `window.dataLayer` contains a consent `update` entry with `analytics_storage: 'granted'`; the banner is gone and stays gone on reload.
3. **Essential-only denies downstream.** Fresh session, click Essential only → cookie reads `{"analytics":false,"marketing":false}`; no GTM script tag is injected (`document.querySelector('script[src*="googletagmanager.com/gtm.js"]') === null`); no `<ins class="adsbygoogle">` renders on an AdUnit-bearing page.
4. **LP suppression.** Cleared cookies → `https://ryan-realty.com/lp/seller-home-value` → no "Cookie notice" region anywhere in the DOM.
5. **Ad-traffic auto-grant.** Cleared cookies → `https://ryan-realty.com/?utm_source=accept-check` → without touching any UI, the consent cookie exists with both flags true (written by the VisitTracker effect).
6. **Explicit choice is never overridden.** Set Essential only, then load `https://ryan-realty.com/?fbclid=TEST` → cookie still reads `{"analytics":false,"marketing":false}`.
7. **Server refuses declined/missing consent.** Browser-UA `POST https://ryan-realty.com/api/visitors/track` with a valid body but `consent: 'declined'` (and again with no consent field) → `{ ok: true, dropped: true, reason: 'consent_declined_or_missing' }`, and no visitor_events row appears for that sessionId.
8. **GPC wins over everything.** Same POST with header `Sec-GPC: 1` and `consent: 'all'` → `{ ok: true, dropped: true, reason: 'gpc_opt_out', … }`; for a session already identified to a CRM person, a `crm_suppressions` row exists afterward (SQL: select from `crm_suppressions` for that person, column names per docs/DATABASE_SCHEMA_SNAPSHOT.md).
9. **Essential-level stripping.** Fire a `page_view` with `consent: 'essential'` and UTM params in the payload → the stored visitor_sessions/visitor_events rows for that sessionId carry no UTM/geo/listing-meta values (verify against the column list in docs/DATABASE_SCHEMA_SNAPSHOT.md).
10. **Expiry/clearing restores inception.** Delete the consent cookie in DevTools, reload any non-LP page → the banner returns.
11. **D1 repair check (currently RED by design gap — turns green when the target shape ships).** From any public page's footer, a visitor can reach a control that re-opens the consent preferences and flips Marketing off; after saving, `window.dataLayer` shows a consent update with `ad_storage: 'denied'`. Until this passes, /privacy#donotsell's instruction is a promise the site cannot keep.
