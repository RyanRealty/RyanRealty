## 0. CRITICAL REPO RULES (must-know before touching anything)

1. **§0 Data Accuracy is absolute.** Every public number/fact traces to a real source (live Supabase, the MLS, or a cited primary source). Never invent. For market data use the caches (`market_pulse_live`, `market_stats_cache`), never aggregate raw `listings` at request time. Mixed-case `listings` columns must be double-quoted in SQL (`"ListPrice"`, `"StandardStatus"`, `"ListNumber"`).
2. **Draft-first, commit-last.** Public-facing changes need Matt's explicit approval before they go live. The pre-commit hook **blocks** public-copy commits; once Matt has approved, commit with `DRAFT_FIRST_OK=1 git commit ...` (audit-logged). Internal/infra/docs commit normally.
3. **Brand voice is gated** (`ci:brand-voice`). Hard fails: em-dashes (—), en-dashes (–), semicolons, exclamation marks in body, and banned words (stunning, nestled, boasts, charming, pristine, **luxurious**, premier, boutique, exclusive, world-class, elevate, seamless, robust, curated, bespoke, etc.). NOTE: plain **"luxury"** and **"high-end"** are NOT banned (only "luxurious" and "luxury concierge") — so the luxury-homes page is fine.
4. **No ad-hoc schema SQL.** Read `docs/DATABASE_SCHEMA_SNAPSHOT.md` + `docs/DAL_INDEX.md` before querying. Raw `.from('listings')` outside `lib/data/` is gate-blocked (G1). Audit-only queries via `mcp__supabase__execute_sql` are fine when prefixed with `-- audit: <reason>`.
5. **Silent commit failures.** The pre-commit runs the full vitest suite. `git commit -q ... | tail` MASKS failures — always read the real output, and after pushing confirm `git rev-list --left-right --count origin/main...HEAD` is `0 0`. The pre-PUSH hook runs a full `next build` (~2 min) — give pushes a 300s timeout.
6. **Opus orchestrator:** delegate bulk research/enumeration to subagents (`general-purpose` for web research, `Explore` for read-only codebase sweeps). Keep architecture + final review on the main thread.

## 3. KEY DATA LOCATIONS (for the next session)

- **GSC performance** lives in Supabase `marketing_channel_daily` (no live API auth needed):
  ```sql
  -- audit: SEO quick-win queries (page 1-2, impressions, low clicks)
  WITH q AS (
    SELECT replace(scope_id,'query:','') AS query,
      sum(value) FILTER (WHERE metric='impressions') AS impr,
      sum(value) FILTER (WHERE metric='clicks') AS clicks,
      avg(value) FILTER (WHERE metric='position') AS pos
    FROM public.marketing_channel_daily
    WHERE channel='gsc' AND scope='campaign' AND date > now()-interval '28 days'
    GROUP BY 1)
  SELECT query, round(impr)::int AS impr, round(clicks)::int AS clicks, round(pos,1) AS pos
  FROM q WHERE impr >= 20 AND pos BETWEEN 3.5 AND 20 ORDER BY impr DESC LIMIT 25;
  ```
  Also: `scope='page'` (per-URL), `scope='account'` (totals). Channels also include `gbp`, `meta_page`, `instagram`, `x`, `youtube`.
