## Fixes

**`app/cities/[slug]/page.tsx`** — three coordinated changes, because binding the badge to the SFR count
over an all-types map would have swapped one mismatch for another:
1. `:183` `getCityListings(..., propertyType: 'A', ...)` — every sibling geo map (community,
   neighborhood, subdivision, zip, homepage) is SFR; the city page was the sole outlier.
2. `:475` `totalActive={activeCount ?? mapFeatures.length}` — matches the pattern all six sibling pages
   already use.
3. `:481` subtitle back to "Every active single-family listing with a {city} address."

The voice session had changed this subtitle to "every property type", which made the *claim* honest
against an all-types query but left the page internally inconsistent — hero SFR beside an all-types map.
Filtering the query is the stronger fix: claim, badge, hero, and every sibling page now agree.

The 1500-row cap also stops binding once the pull is SFR-only (Bend SFR active ≈ 499).

**`app/open-houses/[city]/page.tsx`** — added `countNoun`, so the badge labels open houses as open
houses. Count left as the geolocated subset, which is what a map can honestly badge.
