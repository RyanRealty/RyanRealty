# C-14 · Fixed-chrome collision

Census: every `.kb-bc` caller passing `overlay` — the crumb is `position:absolute` with a hardcoded
`top` offset, sitting under a `position:fixed` topbar whose height it does not know.

## 10 affected routes (all `overlay` callers)

`cities/[slug]` · `communities/[slug]` · `zip/[zip]` · `cities/[slug]/[neighborhoodSlug]` ·
`housing-market/[...slug]` · `contact` · `area-guides` · `tools/appreciation` ·
`tools/mortgage-calculator` · `tools/rental-property-calculator`

**census_count = 10 (one CSS rule serves all) · fixed_count = 10**

## Measured before the fix — `/cities/bend`

| viewport | topbar bottom | crumb text top | overlap |
|---|---|---|---|
| 375 | 66px | 52px | **14px** |
| 768 | 66px | 60px | **6px** |
| 1280 | 67.9px | 60px | **7.9px** |

The topbar's height is content-driven (`padding:16px 24px` around the wordmark), which is why it is
66px on mobile rather than the 64px the old offsets assumed. Mobile was worst because a
`@media(max-width:760px)` rule pulled the crumb *further up*, to `top:52px`.

## Fix

One rule: `top:60px` → `top:76px`, and the mobile override deleted (the topbar is the same 66px at
375 as at 768, so pulling the crumb up there was never right).

This is the same defect the `belowNav` prop fixed for no-hero pages on 2026-07-15 — its docstring
records "the wordmark printed over the trail". The ten `overlay` callers never received that fix.
