## Fix applied

`propertyType: 'A'` added to all 6 `getListingTiles` call sites feeding a map whose subtitle claims
single-family. The property-type narrowing must happen at the tile fetch because the upstream
`listings_in_boundary` RPC filters only `StandardStatus='Active'`.

This also aligns each map with the hero count directly above it, which on all three pages is already an
SFR count (`activeSet.count`, `inBoundaryCount ?? pulse.activeCount`, boundary/registry chain).

## Carried finding — NOT fixed here

`supabase/migrations/20260528060000_listings_in_boundary_rpc.sql:43` comments the RPC as returning
"active SFR-ish listings", but its only predicate is `where l."StandardStatus" = 'Active'`. The comment is
wrong. **Not edited**: the migration is applied, and rewriting applied migrations trips `ci:migration-drift`.
Every call site now narrows property type itself, so behaviour is correct. Correct the comment in a future
migration that touches this RPC for another reason.
