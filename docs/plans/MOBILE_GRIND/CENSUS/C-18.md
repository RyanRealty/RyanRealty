# C-18 · Geo resolution ladder (infrastructure)

`lib/data/geo/resolveGeoScope.ts` — one resolver for "what does this geography contain?", because three
geo types answer it three different ways and every caller was re-deriving it inline. That is the shared
root cause behind C-01, C-02, C-19 and C-20.

| type | membership |
|---|---|
| `neighborhood` | SPATIAL only — GIS polygon via `listings_in_boundary`. No MLS field exists for a Bend district. |
| `community` | REGISTRY — `subdivision_aliases` + `sub_neighborhoods`, or spatial via the resort boundary. **Alias-aware** (literal-name matching undercounts every resort). |
| `subdivision` | MLS `SubdivisionName`, plat polygon as fallback. |

Returns `{ type, slug, label, city, citySlug, polygon, listingPredicate, childSubdivisionSlugs,
subdivisionAliases }`. Reads route through `getGeoBoundaryMapData`; no new query is introduced.

`npm run report:geo-coverage` reads via the documented `boundary_geojson` RPC — no ad-hoc SQL.

## Consequence for C-21 — BLOCKED_MATT, not BLOCKED_TECH

The map component is ready: it already accepts N polygons and frames polygon bounds first. **The data is
not there.** Drawing one outline on the Tetherow map and calling it "the subdivisions in Tetherow" would
show 12% of them and imply the other seven do not exist.

Decision D4 says draw what exists and print an honest count — but D4 assumed partial coverage, not 1 of 8.
Options for Matt:

1. **Source the plats.** Deschutes County DIAL has recorded subdivision plats; ingesting them into
   `boundaries` under `geo_type='subdivision'` is what makes the feature real. This is the only path that
   delivers what was asked for.
2. **Ship at the communities that clear a bar** (Awbrey Glen 3/5, NorthWest Crossing 3/7, Sunriver 7/30)
   and leave the rest to the resort outline they already draw.
3. **Drop the polygon layer** and keep pins-only.

Not an option: synthesizing a hull from listing points. CLAUDE.md §7 / C6 — a shape drawn around listings
is not a boundary, and publishing one as if it were is a §0 violation.

## Correlation worth noting

The 5 communities with no polygon of their own — Mt Bachelor Village, Inn of the 7th Mountain, Rivers
Edge, Mountain High, Crooked River Ranch — are **exactly** the set `ci:gates` already warns about for
missing `RESORT_IMG` keys. They are the thinnest registry entries across every dimension, and they are
the ones C-10's silent `if (!img) return null` drops from the rail.

## Gate

`check-geo-scope-usage.mjs` is deliberately NOT written yet: with zero compliant callers it could only be
baselined at "everything violates", which gates nothing. It lands with C-19/C-20, when there is a
compliant pattern to ratchet toward.
