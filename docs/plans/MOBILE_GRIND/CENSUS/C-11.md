# C-11 · Styling applied to the wrapper, not the control

Census: components taking `className` and applying it to a wrapper element rather than the interactive
control they are meant to style.

| component | className target | consequence |
|---|---|---|
| `components/VoiceSearchButton.tsx:62` | wrapper `<div>` | **DEFECT → FIXED** |

Swept `components/**` for the same shape (a `className` prop landing on a container that wraps a single
`<Button>`/`<input>`): no other instance. The remaining wrapper-className components wrap real layout
groups, where styling the container is the intent.

**census_count = 1 · fixed_count = 1**

## Why it rendered as a blank white square

`hs-mic` carries `background:transparent; color:var(--cream-70)` — written for the navy hero. It was
landing on an invisible wrapper. The `<Button variant="outline">` inside kept `bg-background`
(near-white) and the icon inherited the cream colour cascading down from the wrapper: **a cream mic on
a cream square, ~1.1:1.** Both halves were "working"; they were just applied to different elements.

## Fix

1. `className` now lands on the `<Button>` via `cn()`; the wrapper becomes `display:contents` and
   survives only to carry the error message.
2. `variant` stays `outline` — the light surfaces (search filter bar, beside Newest / Save this search)
   expect a bordered control. The hero overrides it through `.kb-root .hs-mic`, which works **only**
   because the class now reaches the button. Specificity (0,2,0) beats Tailwind's (0,1,0), so the
   five `!important` declarations were no longer doing anything and came off.
3. Collapsed the two duplicate `.hs-mic` blocks (`kb.css:227` and `:234`) into one, and deleted the
   dead `.hs-mic.listening` rule + its `hsPulse` keyframes — the component signals listening by
   swapping the icon for a pulsing dot, and never adds that class.
4. `disabled={listening}` removed. It left the only escape as waiting for the recognizer to time out.
   A second tap now calls `stopListening()` through a held `recRef`; `aria-pressed` reflects state.
5. The error `<p>` is `absolute` so a recogniser failure cannot reflow the search row it sits inside.

## Verification (§0) — measured, both mounts

| surface | button background | border | icon | contrast |
|---|---|---|---|---|
| hero (`/`, inside `.kb-root`) | `rgba(0,0,0,0)` | `0px` | cream `rgba(250,248,244,0.7)` | **14.23:1** (was ~1.1:1) |
| search (`/homes-for-sale`) | white | `1px` restored | near-black | high |

First pass set `variant="ghost"`, which fixed the hero but left the search page's mic borderless beside
two bordered neighbours. Caught in verification and reverted — the hero is the surface that needed the
override, not the component's default.
